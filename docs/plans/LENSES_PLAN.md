>
> 来源：与项目所有者的讨论（2026-11-24）。前一步已交付「距你上次来」与「依据」一行（`d01222c`）。

## 1. 目标

主流 AI 日报回答「今天发生了什么」；本项目回答「自上次以来什么真的变了，这些说法有多可靠」。本轮在同一批事件上增加四个视角，让重度读者按「谁在做什么」理解 AI 领域：

| 板块 | 回答的问题 | 主要依据 |
|---|---|---|
| 公司动向 | 各大公司（OpenAI、Anthropic、Google、NVIDIA……）在做什么 | 官方公告等官方来源；媒体报道的动向单独标注 |
| 开源与社区 | 开发者最近在关注、在做什么 | GitHub Trending 与 star 数 |
| 研究 | 新论文与研究成果 | 论文、研究博客与公开评测 |
| 政策与产业 | 监管、出口管制、投融资、并购 | 现有产业方向 |

原则：

- 四个板块都是**同一批事件的视角**，不改变事件归属、证据记录、「距你上次来」。一条进展可以同时属于多个板块（例：英伟达出口管制同时属于公司动向与政策与产业）。
- 公司线按**行动主体**归类，而不是「标题里提到」。只是提到某公司的报道（例：某客服公司用 OpenAI 模型）进入默认折叠的「关于该公司的报道」。
- 不做未经实现与验证的判断：不显示「部分支持」类结论、不显示综合证据强度分。

## 2. 阶段 1：公司动向

1. **补官方信息源**：Google（Gemini 与产品博客）、Microsoft（Copilot、Azure AI 产品公告）、阿里 Qwen 官网、智谱官网、Apple、Amazon。逐个确认可用、抓取稳定后写入 `data/briefing_sources.json`，记录到 [来源接入说明](../SOURCES.md)；失败在「来源状态」中显示。
2. **公司与产品别名表** `data/companies.json`：约 15 家公司，所有者可直接编辑。产品按读者视角分组（例：OpenAI = ChatGPT（含 Codex）/ API 与模型 / 研究与安全 / 公司与政策）；一条进展可带多个产品标签（例：一次模型发布同时属于 ChatGPT 与 API）。
3. **按行动主体归类**：事件主体（`subject`）匹配别名表，或来自该公司官方来源，即为该公司的动向；只在对象或标题中提到的，归为「关于该公司的报道」。
4. **公司线页面**：
   - 官方来源的动向为实心节点；只有媒体报道的为空心节点，标「媒体报道，未见官方」；
   - 发布、重大更新、更正为大节点，其他（介绍、教程、小更新）为小节点；
   - 按产品筛选；每个节点带「依据」一行；
   - 显示「自你上次来，某公司有 N 个动作」。
5. **阅读页证据时间线**：按阶段（发布方陈述 → 测试 → 更正与更新 → 其他报道）排列；缺失的关键阶段用虚线占位并写明「尚未见他方测试」；用分项清单代替证据强度条；相对天数 D0、D1……。节点样式与公司线共用。

## 3. 阶段 2：研究、政策与产业

在现有方向（`topic`）与内容类型基础上重新组织：研究 = 研究方向、研究类内容或论文与研究来源；政策与产业 = 产业方向或产业类内容。主要是导航与页面，不改数据。

## 4. 阶段 3：开源与社区

| 榜单 | 数据 | 回答的问题 |
|---|---|---|
| 增速榜（主角） | GitHub Trending 日榜、周榜（页面上的「新增 star」） | 这几天社区在关注什么 |
| 新项目 | Trending 中近期新建的仓库 | 开发者又做了什么好玩的 |
| 总量榜（参考） | GitHub 搜索接口，AI 主题，按 star 排序 | 社区的基础设施是哪些 |

- Trending 没有官方接口，解析公开网页；解析失败如实显示在「来源状态」，不悄悄变空。
- 只保留 AI 相关项目（仓库描述与主题标签）；疑似刷 star（star 暴涨但几乎没有 fork）标注；列表、教程合集类单独标注。
- 每个项目一句「做什么」：来自仓库描述；README 仍只摘录 MIT/Apache/BSD 许可。
- 不新增数据表、不迁移数据库；榜单按每次更新取得的结果展示。
- `READER_GITHUB_TOKEN`（可选，在 `.env` 中）提高搜索接口额度。

## 5. 交付方式

- 每个阶段一个分支；跑 pytest、前端测试、构建与 `scripts/verify.ps1`；在真实数据副本上做一次小规模核对（例：抽查公司归类）；同步 README 与文档；本机合并到 `main`，不推送。
