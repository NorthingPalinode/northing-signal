# Northing Signal development

- Active product implementation: `docs/plans/AI_INFORMATION_QUALITY_IMPLEMENTATION_PLAN.md` and `docs/CONTENT_ENGINE.md` (2026-11-07). The user explicitly authorized replacing existing architecture and UI rather than forcing legacy compatibility. Users visit voluntarily; no default out-of-app notifications or autonomous actions. Exceptions the user asked for (2026-11-11): the briefing updates itself at 00:00 and 12:00 reader time while the service runs (`Preferences.auto_refresh`, on by default, `service.refresh_due`), and first opening a story version marks it known once (`service.know_on_open`; a reader's "not known" is never overridden). Known marked after the latest update only greys a story; it leaves the focus at the next update.
- The runtime is `backend/northing_signal/briefing/` plus `frontend/src/ReaderApp.tsx`. The retired 0.2 workbench (Goals, Runs, Decisions, Schedules) and the G1–G4 research, evaluation and audit material were removed from `main` on 2026-11-10; they remain on the `archive/research-g1-g4` branch and the `archive/g1-g4-final` tag. Do not restore them to `main` or describe their frozen results as current capability.
- Preserve existing personal data. The old personal database is not migrated automatically; `scripts/export_legacy.py` exports it read-only. Any schema change to `.local/briefing-v2.db` must be a new numbered entry in `store.MIGRATIONS` (never edit an applied one), verified on a copy first, and keep materials, judgments, snapshots, saved items, follows and interactions. A table the briefing projection reads needs revision triggers, or cached views go stale.
- Introduce training or complex agent infrastructure only when measured content-quality gains justify it.
- Keep domain rules independent from HTTP/UI: immutable material revisions, append-only reader actions, no late publication after cancellation, explicit confirmation before tracking starts.
- `baseline` mode does not call a model. Never present fixture or mocked results as live-model validation, and never present repeated AI passes as independent or human validation.
- Judgments are keyed by `POLICY_EPOCH` (`briefing/models.py`), not by the prompt hash. Rewording the prompt keeps existing judgments; bump the epoch only when earlier conclusions should be re-judged, and say so in the change.
- Event membership is persistent (`event_members`): never re-derive or rewrite existing groupings; only a reader's split/merge moves materials. Fuzzy matching stays conservative (exact normalised subject, versions and product words) — a wrong merge hides news.
- Preserve `data/archive/articles.json`, `data/sources.json` and `docs/provenance/` (migration provenance). Publisher statements, reported tests, opinions, search excerpts and model explanations are different evidence types.
- Keep credentials and local user data out of Git. Do not read or copy another project's credentials.
- Development diaries belong in `dev-diaries/` and must remain local. Never stage, force-add, commit, push, or upload that directory or its contents; preserve its root `.gitignore` rule.
- Keep validation proportional: default pytest covers `tests_reader/`; `scripts/verify.ps1` is the normal local check. Run Ruff, frontend tests (`npm test`, pure logic in `frontend/src/reader/`) and the frontend build for relevant changes. The version lives only in `backend/northing_signal/__init__.py`. Prefer a small real-material comparison over duplicate sealing/control scripts (user request, 2026-11-07).
- Frontend `dist` is generated. Change source and rebuild.
- Accounts (2026-11-23, user request for a cloud deployment): one token per account, only its SHA-256 hash stored (`users`). Content (materials, judgments, events, refreshes) is shared; preferences, interactions, follows, follow drafts, visits and snapshots carry `user_id` and every store method for them is scoped to one account. Never return another account's data or run details (`ContentService.visible_run`). Ordinary accounts have daily request and follow limits; shared corrections (split, merge, retry) are admin-only. `READER_AUTH=off` keeps the single local reader (`LOCAL_USER`), which owns all rows written before accounts existed. Do not claim durable checkpoints, vector retrieval or algorithm gains before implementing and verifying them.
- Public digest (`briefing/publish.py`, 2026-11-23, user chose "make it usable by others"): built from a neutral projection (`Preferences()`, no interactions), so reader actions, follows and preferences never reach public pages; it publishes titles, summaries, reasons, evidence labels and source links only, never excerpts or quotes. It writes files to `READER_PUBLISH_DIR`; pushing them anywhere stays the user's own step.
- Calibration (`briefing/calibrate.py`, `label` / `calibrate` commands, 2026-11-24): the owner's human labels in `.local/reader-quality/gold.jsonl`, measured against stored judgments without model calls. Keep them separate from the AI-authored `evaluate` reference; report coverage and complete accuracy next to precision/recall, and tune on the development split before one holdout check. Thresholds live in `READER_THRESHOLD_OFFICIAL` / `READER_THRESHOLD_OTHER` (default 9, the earlier fixed rule).
